Current spec rule (rev 1.93)

§4 subtitle rule: when the summary line carries counts, each count MUST render as a panel count chip: the chip carries its title INSIDE (label first, then the count in the chip ink, tabular numerals); all four chips describe the same globally filtered dataset — blue submissions in the selected window, violet document groups in that window, green distinct documents accumulated till the window end, neutral records currently displayed. Labels state "in / for" vs "till" the month; blue hides under All months. The single funnel mark appears only when the in-panel time filter or an actually-narrowing global filter is active — selecting every available value is not a filter. Chip colours come only from the standardized --pchip-* families; red / amber warning colours are reserved for severity chips and MUST NOT be used by panel chips; a chip whose case does not apply MUST NOT render; a zero count displays 0; the row keeps the §4 subtitle layout (own line, before the .c-card, margin:6px 0, left-aligned) and stays data only.

Implemented: spec §4 and assertion 34 at rev 1.93; dashboard.css carries the four --pchip-* families in all five themes and the .pchip classes; render.js renders this chip row in the Submittals panel. See sample-pchip-filter-indication.html for the full filter-state matrix. Other panels' count subtitles migrate in follow-ups.
