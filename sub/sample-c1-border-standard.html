Border color mode
Current UI spec. Dashboard-UI-Design-Spec.md §4.2 rev 1.59 allows only the .panel edge plus one .sc-board border. It says No third bordered wrapper is permitted. This page intentionally shows a proposed five-border standard for review. It does not change the spec.

Proposed border standard

All five owners use a var(--bw) solid border and a 10 px corner radius. Review colors identify each owner. The one-token view replaces all five colors with --border.

Review notes

  • The page shows five border boxes. The current UI spec allows two border boxes.
  • Review colors identify each owner. The one-token view shows one common border token.
  • The one-token view uses CSS :has(). If the browser does not support it, the review-color view stays active.
  • The table stays attached to the plot bottom. No CSS position: sticky is used.
  • The plot border and the table border meet at the attached edge. A production standard needs a geometry decision for shared edges.
  • Shared corners between borders 3, 4 and 5 use right angles. Outer corners keep the 10 px radius.
  • The table is a native <table> with <caption>, <colgroup>, <thead>, <tbody> and scope. No ARIA table roles and no display:contents are used.
  • The SVG uses preserveAspectRatio='none'. The grid has no padding or border. The plot and table use --bw:1px. Each SVG month band aligns with one table month column.
  • The .c1-grid inherits --c1-gutter and --c1-cols from :root. No self-referencing custom property remains.
  • Control borders, meta-card borders and owner circles are review aids. They are not part of the five proposed borders.
  • No spec, engine, standalone dashboard, test, harness, workplan, log or existing sample file changed.
  • A later spec change needs separate approval. This page gives no approval.
  • Rollback: delete sub/sample-c1-border-standard.html. No other file needs a change.
