  • RC-1 .sev-*{display:inline-block} sits on <td> → the cell leaves the table formatting context; padding, vertical-align, column width and bottom border all change meaning.
  • RC-2 Sev renders at 13 px while the table base is 12 px → baselines cannot align.
  • RC-3 line-height:1.1 vs inherited 1.45 → ≈14.3 px vs ≈17.4 px line box in the same row.
  • RC-4 ⛔ ⚠️ ℹ️ are colour emoji — the fallback font's em box exceeds the text font's, and all three have different metrics.
  • RC-5 <code> has no table-level reset → UA monospace at a different size, and wider.
  • RC-6 Description is free prose that wraps → row height varies row to row.
  • RC-7 vertical-align:top on every cell amplifies the drift.
  • RC-8 Nothing enforces a row height — §7.2's old “Row height ≈ 40 px” was descriptive, never a constraint.

§7.2.6 —

Click a header, or reach it with Tab then Enter / Space. Three states: none → ascending → descending → none. Watch aria-sort and the arrow — unsorted columns reveal the arrow only on hover/focus.

L3 — windowed rendering, 5 000 rows × 27 columns

§7.2.8 —

Only the visible window (±8 rows overscan) exists in the DOM; two spacer rows preserve the total scroll height. The control row reports the full count, so the §4.3 contract is kept. Sorting and export read the same full array — windowing is a rendering detail only. The freeze boundary draws the same single 1 px --border rule as every other divider (§7.2.2).
